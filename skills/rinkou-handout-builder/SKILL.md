# 輪講資料ビルダー

原典の忠実な翻訳と、発表者が理解を助けるための解説を混同せず、一つの提出可能なLaTeX/PDF資料として完成させる。

## 参照ファイルとスクリプトの場所

プラグインとして導入した場合は次の位置にある。

- `${CLAUDE_PLUGIN_ROOT}/skills/rinkou-handout-builder/references/`
- `${CLAUDE_PLUGIN_ROOT}/skills/rinkou-handout-builder/scripts/`

`~/.claude/skills/rinkou-handout-builder/` へ直接置いた場合は、このSKILL.mdと同じディレクトリの`references/`と`scripts/`を使う。以降のパス表記はスキルディレクトリからの相対で書く。

## 最初に確定すること

1. 対象の原典PDF、担当する印刷ページ番号、開始節、終了節を特定する。
2. PDF上の通しページ番号と、紙面に印刷されたページ番号を区別する。範囲判定には原則として印刷ページ番号を使う。
3. 既存の`.tex`、スタイルファイル、図、生成済みPDFがあれば、上書き前に構成と現状を確認する。
4. 終了ページの途中で次節が始まる場合、指定された終了節の末尾で止める。ページ末尾までという理由だけで次節を含めない。
5. 添削済みPDFがある場合は、ページ画像だけでなくPDFの注釈レイヤーを列挙し、ページ、注釈種別、選択箇所、コメント本文を対応づける。

## PDFの読み方

原典PDFはReadツールで直接読む。`pages`でページ範囲を指定でき、図・数式・レイアウトを実際の見た目のまま確認できる。10ページを超えるPDFでは`pages`の指定が必要で、1回のReadで最大20ページまで読める。

- テキスト抽出（`pdftotext`）だけで範囲判定や翻訳を進めない。段組、図中ラベル、数式はテキスト抽出で崩れる。
- Readで読んだ結果と、`pdftotext`で得た文字列の両方を使う。前者は見た目の確認、後者は表記の検索・突き合わせに向く。
- 図の細部（軸ラベル、添字、曲線の重なり）を確認する必要があるときは、`pdftoppm -r 200 -png -f <開始> -l <終了> input.pdf out`で高解像度のPNGを作り、Readで見る。

## 原典との照合と全文翻訳

- 該当する原典ページを最初から最後まで順番に確認する。段落がページをまたぐ箇所を特に注意する。
- 見出し、本文、数式、式番号、例題、解答、図番号、図キャプション、脚注、参考文献番号を保持する。
- 数式記号、変数、添字、符号、積分範囲、単位を原典と照合する。説明のために式を勝手に簡略化しない。
- 原著の文章を自然な日本語へ訳すが、意味の追加は翻訳本文へ混ぜない。訳者による補足は後段の「解説」へ置く。
- 原図中の英語ラベルを残す場合は、対応する英語の近くへ日本語を併記する。図を損なわず併記できない場合に限り、図の直下へ明確な対応を示す。
- 完成前に原典と翻訳をもう一度ページ単位で走査し、各段落の先頭と末尾が対応していることを確認する。

詳細な完了基準は[references/quality-checklist.md](references/quality-checklist.md)を読む。翻訳・解説を書き始める前に、[references/review-informed-style-guide.md](references/review-informed-style-guide.md)も読み、文体、用語、図、数式の組版規則を適用する。

## 文体・用語を整える

- 原文の意味と論理上の主語を保ちながら、日本語では能動態を基本とする。`〜される`を機械的に連続させず、自然な主語を補って`〜を定義する`、`〜を表す`のように書く。
- `〜することがわかる`、`〜であることが示される`などを無条件に足さない。認識・推論であること自体に意味がなければ、結論を直接かつ簡潔に述べる。
- 作業前に用語表を作り、翻訳本文、図、キャプション、解説の全体で訳語を統一する。既存資料や研究室の指定語があれば優先する。
- 略語は原則として初出で正式名称、英語、略語の対応を示し、以後は略語へ統一する。略語を持たない語には英語を括弧書きしない。
- 原語をカタカナへ写しただけの訳語は、定着した日本語の術語があればそちらを使う。例として、random processは確率過程、shape factorは形状係数とする。
- 全置換は初出表記まで壊すおそれがある。Editの`replace_all`を使う前に置換候補をGrepで列挙し、初出と2回目以降を分けて確認する。
- 単位は原則として`Hz`、`rad/s`などの標準的な記号を使い、綴り書きと記号を混在させない。
- 語の一部として使う数字は漢数字で書き（二進数、二倍、八進法）、値そのものを指す数字は算用数字で書く（1ビット目、3\,dB、式(2.1)）。
- 原文が段落を分けていない箇所で、読みやすさを理由に段落を追加しない。段落の切れ目は原典に合わせる。
- 強調目的で日本語のかぎ括弧を乱用しない。研究室の指定がなければ、引用符はLaTeXの<code>``...''</code>を使う。
- 添削内容を再利用可能な規則へ反映するときは、添削者名、コメント原文、未公開資料の内容を公開物へ転載せず、指摘を匿名化・一般化する。

## 独立した解説を作る

翻訳本文の後に改ページし、`\section*{解説}`など明示的に分離された章を置く。解説は翻訳の言い換えだけにせず、次のうち対象範囲の理解に役立つ内容を選ぶ。

- 節全体の因果関係や概念間の対応
- 式の物理的・工学的意味
- 導出の省略部分
- 図の読み方
- 理想モデルと実装上の制約
- 例題結果の解釈
- 誤解しやすい点と発表時に押さえる要点

解説の構成や項目数は内容に合わせる。数式を再掲するときも、何を理解させるための式かを文章で説明する。

## 図の扱い

- 原典の図は生成AIで描き直さず、原典PDFから十分な解像度で抽出する。数式・曲線・軸ラベルの忠実性を優先する。
- 抽出には`pdfimages -png -f <ページ> -l <ページ> source.pdf prefix`や、ページを画像化してから切り抜く方法を使う。埋め込み画像として取り出せない図（ベクタ描画）は、`pdftoppm -r 300`でページを高解像度化してから切り抜く。
- 図番号や本文との対応が分かる安定した名前を使う。
- 原則として図本体と原著の図題・キャプションを最後まで含めて切り抜く。LaTeX側でキャプションを再構成する場合は元キャプションを除き、二重掲載を避ける。どちらの場合も、キャプションの断片だけを残さない。
- 切り抜きには図全体と必要なラベルを含め、隣接本文、ページ番号、黒縁を含めない。
- 英語ラベルの訳は図の下へまとめるだけで済ませず、原則として対応する英語の近くへ日本語を併記する。原図を損なわないオーバーレイや画像編集を用い、曲線、軸、数式、記号を覆わない。
- 図は`figure[tbp]`などでページ上端または下端への配置を優先し、段落と段落の間へ強制固定しない。本文との多少の前後は許容し、本文参照と図番号で対応を明確にする。
- 図のためだけに`\newpage`や`\clearpage`を入れない。図の大きさが不可避な場合を除き、図だけのページや大きな空白を作らない。
- 切り抜いた画像は、LaTeXへ配置する前に必ずReadで開いて中身を見る。ファイルが生成されたことと、意図した図が写っていることは別である。
- LaTeXへ配置した後のPDFもReadで見て、元画像が正しくても縮小で読めなくなっていないか確認する。
- 図が必要な位置にあるだけで満足せず、最終PDFに画像オブジェクトとして実際に埋め込まれていることを確認する。

## 数式を読みやすく配置する

- ディスプレイ数式を一つの文の途中へ挟まない。数式前の文章を`次式で表す．`などで一度完結させ、数式後は新しい文として説明を始める。
- 数式だけを連続させず、導入文と、式から何が読み取れるかを簡潔に添える。ただし同じ内容を式の前後で重複して述べない。
- 数式前後の改行や余白はLaTeXの環境に任せ、手動の空行、`\vspace`、改ページで過度に調整しない。
- ディスプレイ数式の直後に空行を置かない。段落が変わり、次の文へ不要な字下げが入る。この誤りは繰り返し起きるため、完成PDFで毎回確認する。
- 既出の式を指すときは`次式`ではなく式番号で参照する。`次式`は直後に置く式に限る。

## 添削済みPDFを反映する

添削PDFのコメントは注釈レイヤーに入っており、ページをReadで見ても`pdftotext`で抽出しても本文としては出てこない。取りこぼしを防ぐため、必ず注釈を列挙してから作業する。

```bash
scripts/extract_annotations.py path/to/reviewed.pdf
```

このスクリプトはページ番号、注釈種別、コメント本文、作成者を一覧にし、最後に総数を出す。選択範囲そのものは取り出さないため、ハイライトや取り消し線がどの語にかかっているかは、出力されたページ番号をたよりにReadで該当ページを見て確認する。`pypdf`が必要で、無い場合は導入方法を表示して終了する。

- 抽出した注釈は1件ずつ、反映済み・対応不要・個別判断のいずれかへ分類する。未確認を残さない。
- 分類の結果は最終報告に含める。件数が合わない場合は、抽出漏れを疑って再確認する。
- 10ページ程度の資料でも注釈が100件を超えることがある。件数に対して指摘の種類は少なく、同種が全文へ散らばる。1件を直したら同種の箇所をGrepで検索し、まとめて直す。
- 用語の変更を求められた場合は、本文だけでなく図中の訳、キャプション、解説まで置換の対象に含める。
- ハイライトや取り消し線は、選択箇所と本文の対応を確認してから直す。コメントの無いハイライトも指摘として扱う。
- スクリプトは注釈の色と色ごとの件数も出力する。色を使い分けている添削では、色が指摘の分類そのものを表す。凡例を示すノート注釈（`以下◯◯ライン`など）を先に探し、色と指摘種別の対応を作ってから残りを処理する。
- 複数の添削者が関わる場合、式の参照方法や訳語の選択で指導が食い違うことがある。担当資料を添削した本人の指示を優先し、食い違いに気付いたら依頼元へ確認する。
- 添削内容を[references/review-informed-style-guide.md](references/review-informed-style-guide.md)のような再利用可能な規則へ一般化するときは、添削者を特定できる情報とコメント原文を残さない。

## LaTeXとPDFの生成

pLaTeXと`dvipdfmx`を使う文書では、画像と色のドライバを統一する。後から読み込まれる`color`系パッケージが`dvips`へ戻すことがあるため、必要なら次のように文書クラスへグローバル指定する。

```tex
\documentclass[dvipdfmx,a4j,onecolumn,oneside,12pt]{jarticle}
```

ビルドには[scripts/build_and_check.sh](scripts/build_and_check.sh)を優先して使う。

```bash
scripts/build_and_check.sh path/to/handout.tex
```

このスクリプトはpLaTeXを2回実行し、`dvipdfmx`でPDFを作り、未解釈の画像命令、未定義参照、ページ数、埋め込み画像数を検査する。既存プロジェクトが別のビルド方式を明示している場合は、その方式を尊重し、同等の検査を行う。

## 最終検証

1. `pdfinfo`でPDFが開け、想定ページ数を持つことを確認する。
2. `pdfimages -list`などで、参照した図がPDFへ埋め込まれていることを確認する。
3. 完成PDFをReadで開き、**全ページ**を目で確認する。20ページを超える場合は`pages`を分けて全ページ読む。読んでいないページを残さない。
4. 空白の図、切れ、重なり、はみ出し、黒四角、文字化け、低解像度、不要な隣接文字がないことを確認する。
5. 図がページ上端または下端へ自然に収まり、図だけのページやページ下部の大きな空白が不必要に生じていないことを確認する。
6. `pdftotext`で、指定範囲の最初と最後、補完した段落、例題、独立解説の見出しを確認する。
7. 用語、略語、単位、受動態、冗長表現をGrepで全文検索し、初出を保ったまま表記が統一されていることを確認する。
8. 添削PDFが入力にある場合は、抽出した全注釈について、反映済み、対応不要、個別判断のいずれかを記録し、未確認の注釈を残さない。
9. 原典の該当ページを再確認し、範囲外の次節が混入していないことを確認する。

修正した`.tex`と完成PDFの場所、翻訳・解説・図・検証の結果を簡潔に報告する。検証前のPDFを完成品として渡さない。
